# 翻译契约（模板）

> 用法：复制本文件到工作目录（如 `.work/CONTRACT.md`），把 `{{...}}` 占位符填好，
> 然后让每个翻译子代理**先读这个文件**再开工。
> 不要把本文件内容内联进每个子代理的 prompt——那样 24 个分片就会有 24 份可能走样的规则。

---

## 任务

把 PHP 语言包分片从 **{{SOURCE_LANGUAGE}}** 翻译为 **{{TARGET_LANGUAGE}}**。

- 输入分片：由调用方在 prompt 中给出
- 输出文件：同名文件写到调用方指定的输出目录
- 输出文件必须是**完整、可用的 PHP 语法行集合**

## 铁律（违反即为失败）

1. **输出行数必须与输入逐行完全一致。** 不得增删行、不得调整顺序、不得合并或拆分条目。
2. **只翻译双引号内的字符串值。** 以下内容逐字节原样保留：
   - 行首结构：`{{ENTRY_PREFIX_EXAMPLE}}`（含变量名、所有方括号与键名）
   - **键名一律不翻译**（单引号内的英文标识符是程序用的，不是给人看的）
   - 行尾的 `";`
   - 空行、`<?php` 等非条目行
3. **转义序列 `\"` 必须原样保留**（反斜杠 + 半角双引号）。
   绝不能改成中文引号 `""` 或裸双引号——那会破坏 PHP 语法或破坏数据。
4. **占位符原样保留，一字不改、不翻译、不增删**，包括但不限于：
   - `%s` `%d` `%i` `%m` `%n` `%y` `%A` 等百分号形式
   - `:name` 冒号形式（如 `:price`、`:clientName`、`:clearDate`）
   - `{php}` 等花括号形式
5. **HTML/XML 实体原样保留**：`&amp;` `&copy;` `&quot;` `&raquo;` `&reg;` `&trade;` `&nbsp;` 等。
6. **HTML 标签、属性、属性值、URL 原样保留**，只翻译标签之间的可见文本。
   - 例：`<a href="clientsadd.php">create a client</a>` → `<a href="clientsadd.php">创建客户</a>`
7. **URL、邮箱、文件路径、代码标识符、数字、单位**原样保留
   （如 `cron.php`、`https://go.example.com/123`、`max_input_vars`、`4-byte UTF-8`、`Ctrl + Click`）。
8. **品牌与产品专有名词保留原文**：{{BRAND_NAMES}}
9. **不得添加任何注释、说明、Markdown 围栏或行号。** 输出文件里只能有 PHP 行。
10. 语言代码行（如 `"en_001"`）**保持原值**，它不是可译文案。

## 语言质量要求

- 译文符合 **{{TARGET_LANGUAGE}}** 的表达习惯：流畅自然，无机械直译痕迹。
- 语气与原文一致：正式提示保持正式，友好引导保持亲切，错误告警保持简洁明确。
- **标点使用 {{PUNCTUATION_STYLE}}**。
  技术场景保留半角：URL/路径/代码内部、占位符周围、HTML 属性内、快捷键、
  字符列表（如 `. _ - @`）、数字与英文缩写之间。
- 英文省略号 `...` 若为界面进行中提示（如 `Generating...`），按目标语言习惯处理，保留省略号形式。
- 句末英文句点译为 {{SENTENCE_TERMINATOR}}；但以占位符或英文标识结尾时不要强行加句号。

## 完成动作

1. 写出对应输出文件。
2. 自查：行数是否与输入一致？每个 `\"` 是否还在？每个 `:placeholder` 是否还在？
3. 回报一句话：`DONE <输出文件路径> <行数>`，并列出任何你拿不准的条目。

> 提醒：调用方会用一个**独立于你**的校验工具复核你的输出。
> 如果你在自查中发现过自己的错误，请如实报告——这比一个漂亮的「0 issues」有价值得多。
