# 同语言字形转换：繁體中文（zh_TW）→ 简体中文（zh_CN）

> 这是 `localize-php-language-file` 的一个特例。流程骨架（预检 → 分片 → 契约 → 并行 → 组装 →
> 独立校验 → 归一化 → 交付）完全不变，变的是**契约内容**和**校验手段**，因为：
> 原文已经是中文，结构校验（langtool）看不出「有没有真的转换完」，
> 必须再加一层**字形/用语**校验（`scripts/residue.py`、`scripts/terms.py`）。

## 与英译中的四个关键差异

1. **只改字形与用语，不改句式。** 原文语义已经正确，译者无权重写。唯一例外是源文自身
   有语法硬伤（如「我們將將您的…」重复「将」）时可做最小修正，并在报告中说明。
2. **本来就是英文的整条值不要翻译。** 语言包里常有尚未本地化的英文条目。
   判断方法：值里没有汉字（`[\u4e00-\u9fff]`）→ 原样照抄。
   `residue.py` 的 `pure-English values modified` 必须为 **0**，否则就是越界改写。
   （若用户明确要求「把英文条目也译成中文」，那是**另一个任务**，要在交付时单独说明。）
3. **占位符/实体/URL/标签的规则与英译中完全相同**——一条都不能少。
   特别注意 `:ot:` `:ct:` 这类成对标记、`&#10;`、`&amp;`、`\"`。
4. **语言代码行**（`$_LANG['locale'] = "zh_TW";`）保持原值，在交付说明里提醒用户部署时改为 `zh_CN`。

## 契约要点

复制 `references/contract-template.md` 后，把「任务」段替换为：

- 这是**同一种语言的字形与用语转换**，不是英译中。
- 没有汉字的整条值原样照抄（不是漏译）。
- 标点沿用原文形式：原文全角就全角，原文半角（`/` `-` `()` `%` `.php`、占位符周边）保持半角；
  `「」` 与 `...`/`……` 一律保持原样，不要互改。
- **同一原文全篇只允许一种译法**，未列入表的词按大陆通用译法处理。

### 保持原样（不是台湾特有，勿误改）

`目前`（标准大陆用语）｜`停用`（＝禁用，大陆通用）｜`建立`（＝创建，两者皆可用）｜
`取得`（＝获取）｜`新增`（＝添加）｜`凭证` 在「登录凭证」里是对的（credentials）｜
`资料` 在「个人资料／联系资料」里是对的（大陆也用）｜`完成` `全部` `立即` `已经` `无法`
`关于` `为了` `对于` `并且` `关闭` `开启` `显示` `隐藏` `展开` `预览` `继续` `升级` `安装`。

> 把上面这些放进「竞争用语」检查表会制造 80% 的噪声。`residue.py` 的默认表已刻意剔除它们。

### 源文常见错误（只转字形，不改语义）

语言包里常混入机器误译：`會議紀要`（minutes）、`桌子`（tables）、`流行音樂 3`（POP3）、
`防晒`（SPF）、`門票／機票`（ticket）、`跑步`（Running）、`敘利亞人`（Syriac）。
按「不改写原文」处理，并在交付说明里列出，让用户决定是否另行修正。
**不要**在翻译任务里顺手修语义——那会让交付物无法与源文对应。

## 字形校验怎么做

```bash
# 首次：装 OpenCC（pip 被沙箱挡住时按下面的办法解压 wheel）
python -c "import json,urllib.request,zipfile,io; \
  m=json.load(urllib.request.urlopen('https://pypi.org/pypi/opencc-python-reimplemented/json')); \
  u=[x for x in m['urls'] if x['filename'].endswith('.whl')][0]; \
  zipfile.ZipFile(io.BytesIO(urllib.request.urlopen(u['url']).read())).extractall('.work/pylibs')"

export OPENCC_PYTHONPATH=.work/pylibs        # Windows: set OPENCC_PYTHONPATH=...

python scripts/residue.py chinese_zh_tw.php chinese.php --report .work/residue.txt
python scripts/terms.py   chinese.php --report .work/terms.txt
```

判定单个字符是否为繁体专用字，**只能**逐字判断：

```python
OpenCC('t2s').convert(ch) != ch     # True → 该字是繁体专用字
```

**绝对不要**拿「简体词表」去匹配整条字符串——简体词里本来就可能含有与繁体同形的字，
那样会把自己的译文全判成错的（本次实战中就有一个子代理因此误报，然后放弃了这条检查）。

`residue.py` 的三个输出要看：

- `residual traditional chars` **必须为 0**（硬问题）
- `pure-English values modified` **必须为 0**（硬问题：越界改写了英文条目）
- `competing vocabulary` 是**提示**，逐条裁决；`目前/停用/资料` 这类不是错误

## 归一化时注意

`langtool normalize` 只按**精确原文**分组。两种不同的 zh_TW 写法表达同一概念时
（`設定錯誤` vs `設置錯誤`），它抓不到——那要靠 `terms.py` 的竞争用语表人工裁决。

用 `--map` 时，**每条都要看一眼上下文再定**：本次 26 组同源异译里，
`停權原因` 出现在 `bannedbanreason`（封禁列表）和 `suspendreason`（服务暂停）两个键上，
统一成「暂停原因」是按主要用途取的决定，要在交付说明里交代。
不指定时工具会按「多数派 + 确定性 tiebreak」自动统一，**这个默认值可能选错**——
本次就自动选成了「封禁原因」，事后需要改回。

## 交付说明要写清的额外三件事

1. `locale` 行仍是 `zh_TW`，部署前是否需要改成 `zh_CN`。
2. **有意保留的英文条目**：列出行号与条数（本次 55 条 / 4469 条），并明确「这不是漏译」；
   同时给出「需要的话可以再跑一遍把它们译成中文」的选项。
3. **源文自身的误译**（如「跑步」＝Running、「桌子」＝tables），本次未改，列出供用户决定。
